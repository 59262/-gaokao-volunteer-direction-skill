# 项目结构与数据流

## 类型判断

当前项目是混合型文档项目，主要由以下部分组成：

- **Codex/Agent Skill**：`高考志愿填报方向选择Skill.md` 定义角色、触发条件、提问流程、边界和报告模板。
- **参考文档**：两个 `.docx` 文件是需求/提问资料，不是运行时依赖。
- **Obsidian 工作区**：`.obsidian/` 保存编辑器状态；其中 `workspace.json` 可能包含打开文件和工作区信息。
- **分析/比较产物**：`_compare_extract/` 和 `_prd_render/` 是提取或渲染产物，可能包含真实考生数据或第三方资料。

## 对话数据流

```text
用户输入
  -> 分阶段信息采集
  -> 信息完整性与数据等级判断
  -> 省份规则/位次/偏好/预算/限制分析
  -> 候选方向与风险提示
  -> 官方核验清单
```

项目没有代码级 API、数据库、构建步骤或自动化数据管道。联网查询、模型日志和数据留存由宿主平台决定，不属于本仓库的实现。

## 修改原则

- 不改变核心提问顺序、风险边界和“不承诺录取”的要求，除非同时更新文档和示例。
- 新增数据时优先使用虚构或脱敏样例，并记录来源、年份和许可证。
- 任何省份规则或院校数据都必须带核验提醒，不能把历史数据写成当年事实。
